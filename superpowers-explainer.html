How Superpowers runs a feature from idea to merged code

Superpowers is not a model and not a tool. It is a set of skills that makes a coding agent stop, plan, and prove its work. This page walks the full path, one gate at a time.

It was made by Jesse Vincent (obra/superpowers) and it fits agents such as Claude Code, Cursor, Codex, and OpenCode.

Watch the gates light up.
  1. 1passed

    Brainstorming

    ▸ The idea becomes a design before any code exists.

    When you say “build X”, the agent does not start typing. It asks what you want to achieve, looks at options, and shows the design back to you in pieces short enough to read.

    The skill is brainstorming. Its output is a design document, and you sign it off line by line.

    Why the gate exists: a wrong design costs minutes on paper and days in code. Cheap arguments happen here, not later.
  2. 2passed

    A fenced work area

    ▸ Isolated branch, clean tests, safe start.

    With a design agreed, the agent sets up a git worktree: a separate directory on a new branch. Your main work area stays untouched.

    The skill is using-git-worktrees. It also runs the test suite once, before any change, to record a clean baseline.

    Why the gate exists: experiments that go wrong get thrown away whole. Nothing bleeds into your working copy.
  3. 3passed

    Writing the plan

    ▸ The design becomes small task cards.

    The skill writing-plans breaks the design into tasks of two to five minutes each. Every card names exact file paths, holds complete code, and ends with a check you can run.

    The bar is simple: an eager junior engineer with no context could follow it and succeed.

    Why the gate exists: small named steps can be checked, re-ordered, or thrown away. One long burst of code cannot.
  4. 4passed

    Building, test first

    ▸ Red, green, then the next card.

    Now the cards get done. You can run them yourself with executing-plans, or hand each card to a fresh subagent with subagent-driven-development. In the second mode a reviewer agent checks every result before work moves on.

    Each task follows test-driven development: write the failing test, write the least code that passes, then move on. Skills test-driven-development and test-anything hold this line. The rule “you aren’t gonna need it” keeps extra features out.

    Why the gate exists: a test that failed first is proof the code does the new thing. Agents that skip it ship confident nonsense.
  5. 5passed

    Review with evidence

    ▸ Claims need proof, not tone.

    Before anything counts as done, verification-before-completion requires the agent to run the commands and show their output. “It should work” is not a state; a green test run is.

    Reviews run both ways. requesting-code-review calls a reviewer agent on finished work, and receiving-code-review makes the builder check claims before it acts on them.

    Why the gate exists: agents fail by declaring success early. This gate makes “done” a measured fact.
  6. 6passed

    Finish the branch

    ▸ Merge, pull request, or clean throw-away.

    The skill finishing-a-development-branch ends the run on purpose: merge it, open a pull request, or delete it. The work area closes cleanly either way.

    Why the gate exists: half-done branches are how repos rot. A decided end is part of the job.

What makes it hold together

Two rules run the whole system. First, the agent loads a small instruction set at startup, the using-superpowers skill, which tells it: before any task, check whether a skill covers the task. That is why the steps above fire without you asking.

Second, process skills come before craft skills. The method decides how to work; a skill like frontend-design only carries out the step it is given. Method first, craft second.

Process first
The agent checks for a covering skill before it acts. No free-hand coding.
Small tasks
Two to five minutes each, with file paths and check steps.
Red, green
A failing test comes before the code that passes it.
Evidence
Done means shown: commands run, output visible.
Long autonomy
Fresh subagents per task and per review keep quality stable for hours without drift.

Put it on your agent

In Claude Code, add the marketplace, then install the plugin:

/plugin marketplace add obra/superpowers-marketplace
/plugin install superpowers@superpowers-marketplace

On OpenCode, fetch the install guide from the repository’s OpenCode notes. Then start a new session and ask for a feature. The first skill will step in on its own.
