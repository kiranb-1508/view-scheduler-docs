Walkwalker.walk()

The walk reads Unity Catalog metadata and follows view_dependencies down to the physical objects that must be fresh. It returns three lists: tables, blockers, and notes.

  • VIEW lists children. Follow each table_full_name.
  • MANAGED, EXTERNAL, MATERIALIZED_VIEW, and STREAMING_TABLE stop the branch and gate the view.
  • A SQL UDF is a note. It has no refresh to wait for, so it never blocks.
  • A cycle, an unreadable object, a view with no dependencies, or a path deeper than 60 is a blocker.
  • done prevents duplicate work. on_stack detects a cycle.

Readclient.read_commits()

All history reads go through one Workspace. Its engine is chosen once, when the object is built.

  • Engine order: an explicit warehouse ID, then $WAREHOUSE_ID, then a live Spark session. Metadata always goes through the SDK.
  • A table or streaming table answers DESCRIBE HISTORY. A materialized view rejects it, so the pipeline event log is read instead.
  • History reads are bounded to the configured day window. Transient failures get 3 attempts; a permanent failure raises at once.
  • The advisor reads metrics. The gate does not. Both go through read_commits().

Classifyhistory.classify() · qualifying()

A commit is a refresh only when its operation says so. The name and the write mode are read together.

  • Full replace: CREATE OR REPLACE, INSERT OVERWRITE, WRITE with mode Overwrite, MV REFRESH.
  • Incremental: MERGE, UPDATE, COPY INTO, STREAMING UPDATE, INSERT, WRITE with mode Append or no mode.
  • Never a refresh: OPTIMIZE, VACUUM, DELETE, and the other maintenance names. Unknown names also do not count, but they are named in the report.
  • A zero-row write still counts. The job ran.
  • finish_times() keeps the first qualifying commit of each local day. qualifying_per_day() feeds the multi-daily (median 2+) and continuous (median 6+) flags.

Decide the safe timerecommend.recommend()

collect_history() summarizes each table. recommend() then intersects the days when every dependency wrote.

  • safe is the latest all-clear clock time, plus the buffer.
  • safe_without_outliers drops late rerun days. An outlier is more than 30 minutes above the median and more than 3 mean deviations.
  • earlier is the median normal all-clear time, plus the buffer. The report labels it EARLIER.
  • A blocking unreadable dependency withholds every time, but keeps the rows and the day-by-day evidence.
  • A buffer that crosses midnight sets the (+1 day) mark.

Decide fresh or stalegate._history_summary() · _verdict_for()

One table is read once per call. A failure is cached too, so a broken dependency is not retried for every view.

  • The latest qualifying write not dated after now decides. A future write is ignored, so clock skew cannot make a stale table look fresh.
  • A daily table gets fresh_hours, default 24. A trusted weekly-ish table gets (longest weekday gap + 1) × fresh_hours.
  • Trust needs every written weekday seen at least twice, and not all seven weekdays. Thin history keeps the 24-hour window.
  • view_scheduler.mode=weekly forces the 8× window. Ignored modes and ignore_tables pass.
  • No qualifying write blocks, unless the table is ignored or ignore_non_daily is set.
  • An unreadable dependency blocks, even when it is marked as ignored. The gate fails closed.

Corrections to the older flow docs

  • A streaming table is not a separate continuous case. It is a gating leaf and is read like any other table.
  • read_latest_commit() is not the gate's question. The gate uses _history_summary(); read_latest_commit() is used by tests only.
